# `sdrmm-modem` catalog

One row per modulation entry: the §5 definition-of-done bundle as a table (MODEM-PLAN §1.2 —
no modulation without a measurement; §5 item 8 — a missing row is a CI failure). The grouping
below mirrors MODEM-PLAN §6 exactly, one section per engine family, so later phases fill rows
in place instead of restructuring the file.

## Columns

- **Entry** — the modulation, named as the harness knows it where a runner exists
  (`cargo xtask ber <entry>`). The runner registry is `ber::catalog::ENTRIES`, which is also
  where the chains, grids, seeds and error budgets behind every committed curve below live —
  one definition, read by the crate's own gate tests and by the command alike. A name in
  parentheses here is a name that command takes.
- **Parameters** — the parameter ranges / configuration the committed measurements were taken
  at (§5 item 8: "parameter ranges").
- **Tiers** — detection tiers implemented; the first listed is the one that gated the entry,
  later tiers are separate merges measured against it (§5 item 2). Planned tiers on pending
  rows are prefixed `planned:`.
- **References / fixtures** — correctness references per §4.1: the closed-form oracle or the
  committed-and-guarded curve, golden vectors, recorded fixtures.
- **Limits table** — the committed §4.3 resistance table.
- **Perf baseline** — the committed §4.2 performance baseline (with the row named where the
  file is shared between entries).
- **Consumers** — repo consumers per §6; "—" means harness-and-TX-only, which changes nothing
  about the required bundle.
- **Status** — `measured` (bundle complete for the tiers listed), `provisional` (committed,
  scheduled to be superseded), `pending (phase N)` (committed scope, no code yet).

## The docs-row rule

`cargo xtask check` enforces this file against the tree in both directions: every file under
`crates/modem/baselines/` and `crates/channels/baselines/` must be named here, and every
baseline path named here must exist on disk. Artifact paths are therefore written
workspace-relative (`crates/…`), exactly as committed — the checker resolves them from the
workspace root. An artifact no row names is a measurement nobody can find, and it stops
gating anything the moment it is forgotten; a row pointing at a deleted artifact is a claim
with nothing behind it.

## Shared infrastructure (not catalog entries)

The §5 bundle applies to modulations; the substrate below the engines is measured through
the entries that consume it, not row by row.

- **`pulse/`** (phase 2) — the one place a pulse shape is defined: rect/LREC/LRC, raised
  cosine and root-raised cosine, the Gaussian premod filter and the GMSK frequency pulse
  (rect ⊗ Gaussian per Murota & Hirade), half-sine, plus the CPM phase-pulse helper
  (q(∞) = ½, so a unit-area frequency pulse steps the carrier phase by exactly π·h — the
  phase-3 engine contract). Every constructor takes an explicit normalisation
  (`Norm::Energy`, Σh² = 1, for amplitude pulses and matched filters; `Norm::Area`, Σh = 1,
  for level-preserving filters and CPM frequency pulses); the wrapped `sdrmm_dsp` designs
  (`design_rrc`, `design_gaussian`) pass through bit-identical under `Norm::Area`, pinned by
  test, as is the TX-RRC ⊗ RX-RRC Nyquist-ISI cascade. Consumers today: the live AIS and
  D-STAR matched filters, all C4FM/GMSK `testgen` shaping, and `ber::reference`'s calibrated
  BPSK link; the phase-3 engines draw from it next. No baseline artifacts of its own — its
  acceptance tests are exact identities, and its measurements arrive through every entry
  shaped by it.

## Linear engine (`linear/` + `constellation/`)

Every row here is the *same code*: `LinearMod` → the shared framing in `ber::catalog::linear` →
`LinearBurstDemod` (or `EnvelopeDemod`) → `Constellation::hard_slice`. What differs between them is
a point table, a per-symbol rotation, a quadrature stagger and a carrier-loop bandwidth — which is
the §3.3 claim ("a code path that special-cases *the* constellation is a defect") stated as
measurements rather than as prose.

**Shared measurement configuration** (all rows): root-raised cosine α = 0.35 span 8 at 8 samples
per symbol — the phase-0 calibration link's own taps — 48 kHz / 6000 baud, no channel-selection
filter (a linear receiver's matched filter *is* its noise-limiting filter), and a 512 + 32 + 16
symbol frame around an 8192-symbol payload whose overhead charges 0.29 dB to Eb. Timing is
**feedforward** (Oerder–Meyr square-law, one estimate per burst); the blind power estimate is
**held** and the scale comes from the §3.4 unique-word anchor. The three measured reasons behind
those choices are in `linear::timing`, `LinearTiming::BURST` and `catalog::linear`'s docs, and the
`16-qam` row commits the tracking-timing comparison that justifies the first.

## Analog (`analog/`)

Analog rows use SINAD/THD vs input SNR in place of BER references (§5 item 4), and the x-axis is
the **channel SNR** — received power over the noise in one message bandwidth, the reference every
closed form below is stated against. The harness is `ber::analog`; the chains are
`ber::catalog::analog`; `cargo xtask ber am|dsb|vsb|ssb|fm|pm` runs them.

**Every analog row has a closed form**, which is the opposite of what "analog" suggests: above
its detector's threshold each family's output SINAD is its input channel SNR plus a constant that
depends only on the modulation's geometry — the **figure of merit**. So these rows are
oracle-matched like the linear ones rather than commit-and-guard, and what is committed instead
is the **knee**: the SNR at which the detector's own nonlinearity ends the straight line.

**Shared measurement configuration** (every row but broadcast FM): 48 kHz, a 3 kHz message, a
1 kHz tone at full drive snapped to an exact bin of the 8192-sample analysis window, 4096 samples
of settle at each end, three realisations summed per point, and 1023-tap filters throughout. That
tap count is set by the *acceptance*, not by the waveform: a figure of merit is stated for a
brick-wall receiver at the message bandwidth, and a soft filter throws away noise inside that band
which the ideal one keeps — so every row reads slightly **above** its oracle, and sharpening the
filters walks the gap back toward zero
(`the_oracle_gap_is_the_receive_filters_own_transition` measures exactly that). The deployed
channels run 129 taps and are none the worse for it: what a short filter costs is an acceptance
against a closed form, not audio.

Read the figures of merit down the table and the whole family tree is one sentence: **amplitude
modulation cannot beat unity because it spends bandwidth on a mirror image, and angle modulation
is unbounded because it spends bandwidth on deviation, which enters squared** — at a threshold
that arrives sooner the more of it is bought. At 30 dB of channel SNR the committed curves read
SSB 30.11 dB, DSB-SC 30.09, narrowband FM 30.37, PM 27.11, full-carrier AM 23.97 and broadcast
FM **45.71**; at 15 dB, below its threshold, that same broadcast FM reads 11.36 dB against single
sideband's 15.15.

**The FM PLL tier's measured value, stated plainly because it is not what the textbook promises.**
A loop extends an FM receiver's threshold because it carries a phase estimate the noise has to
move, where a discriminator takes its argument from one sample pair and gives up the instant the
noise wins. That extension needs a loop *narrow* against the message; this geometry forbids one,
since a 3 kHz message at 48 kHz is a sixteenth of the sample rate and a second-order loop flat
across it must run at a natural frequency comparable to the message itself. The measured result is
the honest consequence: **0 to 1 dB of sensitivity across the whole grid and no measurable
movement of the knee** — both tiers turn over at the same 12 dB point
(`the_fm_loop_tier_buys_sensitivity_rather_than_threshold`). The tier is committed with that
finding attached rather than with the claim it was expected to support.

## Frameworks (`ofdm/`, `multicarrier/`, `spread/`)

**What the four phase-9 rows have in common, stated once.** UFMC, FBMC and OTFS are orthogonal maps
from points to samples — in the *real* field for FBMC, which is the same statement once the OQAM
stagger is taken into account — so under thermal noise alone none of them can be better or worse
than the constellation it carries. Each is therefore held to Gray QPSK's exact closed form shifted
by its own overhead, and **every one of those overheads is arithmetic rather than a fitted
constant**: the block prefix, the filter tail, the guard symbols, the carrier frame. The three land
at −0.11, −0.11 and −0.05 dB. GFDM is the exception because its pulses overlap by construction, and
its distance from that same oracle is *attributed* — prefix plus the inverse's own noise
amplification — rather than tolerated.

**What the three transparent ones are actually for shows up where AWGN cannot see it**, and each
row measures it there: UFMC's out-of-band suppression, FBMC's prefix-free spectrum, and OTFS's
diversity against the nulled subcarrier phase 6 recorded as an uncoded chain's whole loss. That
last one produced the phase's headline finding and it is not the one the literature's summary
suggests — see the note under the table.

The division's cost is read off the taps rather than swept — worst 1.5 dB of noise amplification across the whole allocation, which is what says the prototype's passband actually covers its subband | **Oracle-matched to Gray QPSK's exact closed form, shifted by the filter tail's own overhead** — `10·log₁₀((N + L − 1)/N)` = 0.969 dB, a closed form of the geometry: a receiver integrating `N + L − 1` samples collects that ratio more noise than one integrating `N`. Worst penalty **−0.109 dB** (`crates/modem/baselines/multicarrier/ufmc_awgn.json`, 1e-3 at 7.68 dB). What the waveform is *for* is measured where AWGN cannot see it: **>25 dB of out-of-band suppression** two subbands past the allocation edge, against the `1/f` skirt a CP-OFDM rectangle radiates | shares the GFDM table's axes (`crates/modem/baselines/multicarrier/gfdm_zf_limits.json` is the measured one; this receiver is strictly better conditioned on every one of them and carries no acquisition either) | `crates/modem/baselines/multicarrier/multicarrier_perf.json` (`ufmc_20m`: 476.3 Msamples/s, ≈23.8× real time at 20 MHz — one transform and a per-bin division is all it is, and it is fifteen times the dense receiver above) | — (5G-adjacent) | measured (single tier) |
| FBMC/OQAM (`fbmc`) | 64-subcarrier bank, 48 allocated, **PHYDYAS prototype at overlapping factor 4** (Bellanger 2010 §2.1) — 256 taps, unit energy, generated from three published coefficients rather than transcribed — 32 payload symbols with 4 guard symbols at each end, **no cyclic prefix at all**. Each subcarrier carries one *real* symbol every M/2 samples instead of one complex symbol every M, so the rate is OFDM-without-prefix's | **matched analysis bank → de-rotate by `j^{m+n}` → take the real part.** A filter this well localised cannot be orthogonal in the complex field (Balian–Low), so FBMC is orthogonal only in the *real* one: the OQAM phase puts a neighbour's leakage on the imaginary axis of the wanted symbol, where `Re` discards it. The interference is not small — it is orthogonal, which is stronger — and the module asserts exactly that, on neighbouring subcarriers whose complex inner product is 0.1 and whose real projection is 1e-3. A measured trap came with it: the prototype's centre is `KM/2` and **not** `(KM−1)/2`, and referencing the carrier half a sample away leaves a residual the real projection cannot discard | **Oracle-matched to Gray QPSK, shifted by the guard symbols' overhead** — `10·log₁₀((T + 2G)/T)` = 0.969 dB, the energy of the guards the prototype's four-symbol ramp needs and which are radiated but never counted. Worst penalty **−0.105 dB** (`crates/modem/baselines/multicarrier/fbmc_awgn.json`, 1e-3 at 7.73 dB). The prototype's own stopband, computed from the taps: −20 dB one subcarrier spacing away, −35 dB two | shares the GFDM table's axes, for the same reason UFMC does | `crates/modem/baselines/multicarrier/multicarrier_perf.json` (`fbmc_20m`: 7.4 Msamples/s, **0.37× real time at 20 MHz**). This receiver does *not* keep up, and the number is committed rather than hidden: the analysis bank is written in direct form — one convolution per subcarrier per slot, `O(M·KM)` — which is the definition rather than the implementation. The polyphase form every deployed filter bank uses is `O(M log M)` per slot and is a second merge with its own baseline | — (5G-adjacent) | measured (single tier) |
| OTFS (`otfs`) | A 48 × 16 **delay–Doppler** grid precoded onto the time–frequency grid a CP-OFDM frame already carries — 16 symbols of the 64-point/16-prefix 802.11a/g-like geometry. **OTFS is a precoder, not a carrier**, which is why this row consumes another entry rather than duplicating one, and why its overhead is the carrier frame's unchanged: a unitary precoder radiates nothing of its own | **ISFFT → CP-OFDM → one-tap equalise → SFFT.** Measured through the genie receiver deliberately: the acceptance is the *precoder's* transparency, and an acquiring receiver's own costs are already committed on the phase-6 rows | **Oracle-matched to Gray QPSK shifted by the carrier's own framing overhead**, worst penalty **−0.053 dB** (`crates/modem/baselines/multicarrier/otfs_awgn.json`, 1e-3 at 9.06 dB) — the closest any framework row in the catalog sits to its constellation, which is what "the precoder costs nothing" means as a number. Two properties are asserted without a channel at all: one delay–Doppler symbol occupies **every** time–frequency bin at exactly `1/√(MN)`, and a lone time–frequency bin spreads evenly back — the same identity read from both ends | `crates/modem/baselines/multicarrier/otfs_limits.json` — sensitivity 6.49 / 9.07 / 10.64 dB, static CFO 15.6 ppm of the sample rate, drift bracket-bound, sample clock 48 ppm, IQ gain 1.93 dB, IQ phase 6.6°, static-indoor 2.70 dB, timing 0.0 samples (the genie is told where the frame starts). Every row is *tighter* than the GFDM table's, and structurally so: a precoder spreads each symbol over the whole frame, so an impairment that damages part of the frame damages every symbol | `crates/modem/baselines/multicarrier/multicarrier_perf.json` (`otfs_precoder_20m`: 726.1 Msamples/s of carrier, ≈36× real time at 20 MHz — two small transforms on top of a carrier already paid for) | — (research / 5G-adjacent) | measured (single tier) |

**The OTFS finding, because the pair of numbers is the result.** Spreading every symbol over every
subcarrier turns a *localised* failure into a *shared* one, and whether that is an improvement is a
property of the equaliser rather than of the precoder. Through the same deep null, at the same
Eb/N0, with the same genie channel:

- with a **zero-forcing** one-tap equaliser OTFS is *worse* than plain CP-OFDM, by more than a
  factor of two — dividing by a near-null multiplies that bin's noise by `1/|H|²`, and the despread
  then shares that amplified noise over every symbol in the frame instead of losing one subcarrier's
  bits;
- with an **MMSE** one, which bounds the amplification instead of inverting it, OTFS is ahead by
  more than a factor of two, and plain OFDM keeps the ~1/96 error floor one dead subcarrier out of
  48 gives it whatever the SNR.

Both are asserted in `crates/modem/tests/multicarrier.rs`
(`what_otfs_spreading_buys_depends_entirely_on_the_equaliser`), and neither is quoted without the
other.
